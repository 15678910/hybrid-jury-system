# 수사·기소 분리 법률 쟁점 분석 — 설계와 데이터 스키마

> 2026-08-09 작성. 대상: 공소청법 · 중수청법 · 국과수 관련 법령 · 형사소송법 개정
> 목적: 조문 단위 비교와 제기된 우려의 사실 확인, 그리고 보완·대안 제시

---

## Ⅰ. 이 문서의 쓰임

데스크탑 세션이 **무엇을 어떤 형식으로 수집할지** 정해 두는 문서다.
수집이 끝나면 이 스키마대로 `src/data/` 에 넣고 화면을 붙인다.

---

## Ⅱ. 절대 원칙 (CLAUDE.md 2026-03-18 사건 재발 방지)

1. **조문 내용은 원문에서만.** 추론으로 채우지 않는다
2. **「목적·역할」은 국회 심사보고서·제안이유에서만 인용.** 없으면 빈칸
3. **「우리 안」과 「타 안」을 반드시 분리 표기.** 사용자 제안을 특정 정당·기관의 입장으로
   적는 순간 그 표는 오염된다
4. **정책 판단과 사실 확인을 섞지 않는다.** 「어느 조직으로 옮기는 것이 이상적인가」는
   사실이 아니라 우리 판단이다
5. **확인 불가는 빈칸 + `verified: false`.** 채우지 말 것
6. 보도 인용은 **최소 2개 교차**, URL 필수

## Ⅲ. 수집 대상

### 1. 법령 원문 → `docs/bills/` 에 텍스트로 저장

| 자료 | 출처 | 파일명(예) |
|---|---|---|
| 공소청법 | 국가법령정보센터 | `공소청법_원문.txt` |
| 중수청법 | 국가법령정보센터 | `중수청법_원문.txt` |
| 국과수 관련 법령 | 국가법령정보센터 | `국과수_관련법령.txt` |
| 검찰청법(폐지 전 현행) | 국가법령정보센터 | `검찰청법_현행.txt` |
| 형사소송법 개정안 | **이미 보관됨** | `2220257_법사위안_추출텍스트.txt` |

> 텍스트로 저장하는 이유는 `docs/bills/README.md` 참조 — 세션에 따라 법령 사이트가
> 차단되므로, 저장해 두면 네트워크 없이 `grep` 으로 대조할 수 있다.

### 2. 국회 심사보고서 → 「목적·역할」의 유일한 1차 근거

의안정보시스템에서 각 법안의 **심사보고서·검토보고서**를 받아 같은 폴더에 저장.
제안이유, 주요내용, 전문위원 검토의견에 목적과 쟁점이 적혀 있다.

### 3. 쟁점별 보도 → 최소 2개 교차, URL 기록

## Ⅳ. 데이터 스키마

### 1. 법률 단위 — `LAWS`

```js
{
    id: 'prosecution-office-act',
    name: '공소청법',
    formalName: '',              // 정식 명칭 — 원문 확인 후 기재
    lawNumber: '',               // 예: 제21490호
    promulgated: '',             // 공포일
    effective: '',               // 시행일
    replaces: '검찰청법',         // 대체·폐지 대상
    sourceFile: 'docs/bills/공소청법_원문.txt',
    sources: [{ name: '', url: '' }],
    verified: false,
}
```

### 2. 조문 비교 단위 — `ARTICLE_DIFFS`

```js
{
    lawId: 'prosecution-office-act',
    article: '',                 // 개정 후 조문 번호
    title: '',                   // 조문 제목
    before: {
        law: '',                 // 예: 검찰청법 제4조
        text: '',                // 원문 그대로. 요약 금지
    },
    after: {
        law: '',
        text: '',
    },
    change: '',                  // new | deleted | moved | modified | unchanged
    purpose: {
        text: '',                // 심사보고서·제안이유 인용
        source: '',              // 예: 심사보고서 p.12
    },
    note: '',                    // 읽을 때 주의할 점
    verified: false,
}
```

> `before.text`·`after.text` 는 **원문 그대로** 넣는다. 요약하면 나중에 대조가 안 된다.

### 3. 쟁점 단위 — `ISSUES` (이 분석의 핵심)

```js
{
    id: 'ndfa-transfer',
    title: '대검 과학수사부는 어디로 가야 하는가',
    category: '',                // 조직 | 권한 | 절차 | 시행시기 | 통제
    relatedArticles: [],         // 관련 조문 id 배열

    // ① 제기된 우려 — 누가 말했는지 반드시 기록
    concern: {
        claim: '',
        raisedBy: [
            { who: '', when: '', source: '', url: '' },
        ],
    },

    // ② 사실 확인 — 조문상 성립하는가
    factCheck: {
        verdict: '',             // 성립 | 부분 성립 | 불성립 | 판단 불가
        reasoning: '',
        basis: [
            { type: '', ref: '', url: '' },   // 조문 | 심사보고서 | 보도
        ],
    },

    // ③ 우리 안 — 반드시 「우리 안」으로 표기
    ourProposal: {
        text: '',
        rationale: '',
        isPolicyJudgment: true,  // 사실이 아니라 판단임을 명시
    },

    // ④ 타 안 — 출처 있는 것만
    otherProposals: [
        { who: '', text: '', source: '', url: '' },
    ],

    status: 'draft',             // draft | verified | published
}
```

### 4. 다룰 쟁점 목록 (초기)

| id | 쟁점 | 성격 |
|---|---|---|
| `ndfa-transfer` | 대검 과학수사부의 이관처 | 조직 · **정책 판단** |
| `prosecution-maintenance-gap` | 공소유지 공백 우려 | 권한 · 사실 확인 가능 |
| `search-seizure-recording` | 압수수색 의무녹화 (2027.8 시행) | 절차 · 시행시기 |
| `crime-intelligence-officer` | 범죄정보기획관 | 조직 · 통제 |
| `police-power-concentration` | 경찰 권력 비대화 | 통제 · **핵심 쟁점** |
| `investigation-intel-merge` | 수사와 정보의 결합 위험 | 통제 |

> 각 쟁점은 「우려 → 사실 확인 → 보완·대안」 순으로 채운다.
> **우려를 그대로 옮기지 말고, 조문으로 검증한 뒤 성립 여부를 적는다.**

### 5. 되돌리기 방지 — `IRREVERSIBILITY`

```js
{
    id: '',
    lever: '',                   // 수단
    mechanism: '',               // 어떻게 작동하는가
    strength: '',                // high | medium | low
    cost: '',                    // 도입 비용·난이도
    precedent: [                 // 국내외 선례
        { case: '', source: '', url: '' },
    ],
    caveat: '',                  // 법적 한계
    verified: false,
}
```

**초기 항목 넷** (내용은 검증 후 확정)

| lever | 강도 | 한계 |
|---|---|---|
| 헌법에 올린다 | **high** | 개헌 절차의 정치적 난이도 |
| 조직·인력·예산을 실물로 이전한다 | medium | 시행 초기 진행도에 좌우 |
| 시민을 이해관계자로 만든다 (참심제·시민기소심사위) | **high** | 제도 정착에 시간 필요 |
| 성과를 법정 공표 사항으로 둔다 | medium | 지표 설계에 따라 효과 차이 |

> ⚠️ **법률로 개정정족수를 가중하는 방식은 넣지 않았다.** 후법우선 원칙과
> 국회 입법권의 성격상 효력이 의심스럽기 때문이다. 다만 이 판단은 **헌법학
> 문헌으로 검증이 필요**하며, 검증 전까지 `verified: false` 로 둔다.

## Ⅴ. 화면 구성 (수집·검증 후)

`ReformAnalysis.jsx` 에 탭을 하나 더 두는 방식을 권한다. 새 페이지보다
기존 검찰개혁 분석과 나란히 두는 편이 맥락이 산다.

```
[검찰 조직 개편] [법안 비교] [조문별 문제] [★ 시행 후 쟁점]  ← 새 탭
```

탭 안의 구성:

1. **법률 개관** — 공소청법·중수청법·국과수 각각의 시행일과 대체 관계
2. **조문 대비표** — 클릭하면 현행/개정 원문이 펼쳐짐
3. **쟁점 카드** — 우려 → 사실 확인 → 우리 안 (색으로 구분)
4. **되돌리기 방지** — 별도 절

> 「우리 안」은 화면에서도 **시각적으로 구분**해야 한다. 색·아이콘·라벨 중
> 최소 둘을 써서 타 안과 혼동되지 않게 한다.

## Ⅵ. 작업 순서

| 단계 | 내용 | 어디서 |
|---|---|---|
| 1 | 법령 원문 4건 수집 → `docs/bills/` | 🖥️ 데스크탑 (한국 IP) |
| 2 | 심사보고서 수집 → `docs/bills/` | 🖥️ 데스크탑 |
| 3 | 조문 대비표 작성 (`ARTICLE_DIFFS`) | 어디서든 (원문이 저장돼 있으면) |
| 4 | 쟁점별 보도 수집·교차 확인 | 🖥️ 데스크탑 |
| 5 | `ISSUES` 채우기 — 우려/사실확인 | 어디서든 |
| 6 | 우리 안·되돌리기 방지 작성 | 어디서든 |
| 7 | 화면 구현 · 배포 | 어디서든 (배포는 승인 필요) |

**1·2·4 는 원격 세션에서 불가능하다** — 국회·법령·언론 도메인이 차단된다.
데스크탑 세션에서 먼저 수집해 두면 나머지는 어디서든 진행할 수 있다.
