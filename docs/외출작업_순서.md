# 외출해서 작업하는 순서 (노트북·태블릿 → 데스크탑 Claude Code)

> 2026-08-08 작성 · 2026-08-17 보완. 목적: 밖에서도 **집에서와 똑같이** 작업하기.
> 원리는 하나 — 노트북·태블릿은 **화면과 키보드 역할만** 하고, 일은 전부 데스크탑에서 일어난다.
> 그러므로 함수 배포·로컬 프리뷰·`public/` 파일 읽기가 **전부 된다.** 제약이 없다.

> **크롬 원격은 폴더가 안 보이는 원인이 아니다.** 원격으로 들어가서 **로컬 세션**을 열면
> 폴더가 잘 보인다. 2026-08-17 에 안 보였던 이유는 원격 때문이 아니라 그 화면에서
> **사이드바의 예전 대화를 클릭**했기 때문이다. 아래 「헷갈리기 쉬운 것 ①」 참조.

## 0. 나가기 전에 (데스크탑에서 한 번)

- [ ] **데스크탑을 켜 둔다.** 끄면 접속할 수 없다
- [ ] **절전 해제** — 설정 → 시스템 → 전원 → 화면 및 절전 → 「절전 모드」를 **안 함**
      (화면 끄기는 그대로 둬도 접속에 지장 없다)
- [ ] 크롬 원격 데스크톱이 **Online** 인지 확인

작업하던 Claude Code 창은 **켜 둔 채 나가도 된다.** 원격은 화면만 끊길 뿐
데스크탑의 프로그램은 계속 돌기 때문에, 도착해서 그대로 이어받을 수 있다.

---

## 1. 접속 (노트북·태블릿)

1. 크롬에서 **`remotedesktop.google.com/access`**
2. 「Remote devices」의 **`내-K-VOTE-PC`** 클릭
3. **PIN** 입력
4. 위쪽 모니터 탭에서 **하나만** 선택 (`LG FHD` 또는 `S22C450`)
   → 두 대를 같이 보면 글씨가 절반 크기가 된다
5. **`F11`** 로 전체 화면 — 노트북 작업표시줄이 사라져 오조작을 막는다

여기서부터 화면에 보이는 모든 것은 **데스크탑의 것**이다.

### 글씨가 너무 작을 때

데스크탑 해상도가 노트북 화면보다 크면 통째로 축소돼 들어온다. 두 가지 길이 있다.

- **원격 창의 옵션 패널**(화면 가장자리 화살표)에서 크기 조정을 끈다
  → 축소하지 않고 원래 크기로 보이고, 화면 밖은 스크롤로 이동
- **데스크탑의 해상도를 낮춘다** — 원격으로 들어간 상태에서 데스크탑 디스플레이 설정을 바꾼다
  → 근본 해결. 노트북 화면 크기에 가깝게 맞추면 축소가 일어나지 않는다

2026-08 에 「노트북에서 작업할 수 없을 만큼 작게 보인다」는 문제가 있었다. 원인은
윈도우 버전 차이가 아니라 **해상도 차이로 인한 축소**였다.

## 2. Claude 열기

> ⚠️ **여기가 유일하게 틀리기 쉬운 단계다.** 원격 화면 안에서 열더라도
> **사이드바에서 예전 대화를 클릭하면 클라우드 세션**이 되어 데스크탑 폴더를 못 본다.
> 반드시 **폴더를 지정해 새로** 시작해야 한다.

**A. 이미 켜져 있으면** — 작업표시줄에서 그 창을 클릭. 나가기 전 상태가 그대로 이어진다.
(단, 그 창이 로컬 세션이었어야 한다. 의심되면 3단계로 확인)

**B-1. 데스크탑 앱으로 여는 경우** — 평소 쓰는 방식

1. 작업표시줄(또는 트레이 `∧`)의 **Claude** 아이콘 클릭
2. **새 대화**를 시작하면서 **`hybrid-jury-system` 폴더를 지정**한다
   → 사이드바의 예전 대화를 클릭하면 안 된다
3. 입력창 위에 **브랜치 칩·「PR 생성」 버튼이 없으면** 로컬이다

**B-2. 터미널로 여는 경우** — 확실히 로컬인지 확인하고 싶을 때

1. 작업표시줄의 **탐색기**(노란 폴더) 클릭
2. 왼쪽 **바탕 화면** → **`hybrid-jury-system`** 폴더로 들어간다
3. 위쪽 **주소창을 클릭** → **`powershell`** 입력 → 엔터
4. 검은 창에 **`claude`** 입력 → 엔터

> 탐색기 왼쪽에 `Google Drive (G:)`, `컬럼`, `형사소송법` 이 보이면 데스크탑 것이 맞다.

> **창이 안 보이면 다른 모니터를 확인한다.** 데스크탑은 모니터가 두 대(`LG FHD`·`S22C450`)인데
> 원격에서는 한 번에 한 대씩 본다. 방금 연 창이 안 보는 쪽에 열렸을 수 있다.
> 위쪽 모니터 탭을 바꿔 확인하고, 창을 옮기려면 `Win + Shift + ←` / `→`.
> 작업할 창을 한쪽 모니터에 모아 두면 탭을 오갈 일이 없다.

## 3. 제대로 열렸는지 확인

두 가지를 확인해야 한다 — **어느 컴퓨터인가**, 그리고 **로컬 세션인가**.

**① 로컬 세션인가** — Claude 에게 시킨다. 이것이 가장 확실하다.

```
functions/.env 파일이 있는지 확인해줘
```

| 결과 | 뜻 |
|---|---|
| 있다 | ✅ 로컬 세션 — 데스크탑 폴더를 본다 |
| 없다 | ❌ 클라우드 세션 — 창을 닫고 **폴더 지정해 새로** 시작 |

`functions/.env` 는 `.gitignore` 로 막혀 GitHub 을 건너올 수 없다. 그래서 이 파일이
보인다는 것은 실제 폴더를 직접 보고 있다는 뜻이 된다.

**② 어느 컴퓨터인가** — 터미널이면 `hostname`, Claude 에게 시켜도 된다.

| 결과 | 어디 |
|---|---|
| `DESKTOP-1PLMHMN` | 🖥️ 데스크탑 ✅ |
| `DESKTOP-GOLPA77` | 💻 노트북 ❌ — 창을 닫고 원격 화면 **안쪽**에서 다시 |
| `vm` 등 리눅스 이름 | ☁️ 클라우드 ❌ |

Claude Code 안에서는 화면 상단의 경로(`~\Desktop\hybrid-jury-system`)로도 확인된다.

## 헷갈리기 쉬운 것 두 가지

### ① 원격 화면 안에서 열어도, 「이어서 열면」 클라우드다

| 세션의 종류 | 도는 곳 | 폴더가 보이나 |
|---|---|---|
| **로컬 폴더를 열어 새로 시작한 세션** (앱·터미널 어느 쪽이든) | 그 컴퓨터 | ✅ |
| **예전 대화를 이어 연 세션** (사이드바·링크·웹) | 클라우드 | ❌ |

**앱의 종류로는 판별할 수 없다.** 데스크탑 앱 안에서도 클라우드 세션이 열린다.
「주소창이 보이면 브라우저」 같은 기준은 틀렸다 — 2026-08-17 에 이렇게 잘못 안내했다.

구분은 둘 중 하나로 한다.
- **화면**: 입력창 위에 브랜치 칩(`claude/…`)과 「PR 생성」 버튼이 보이면 **클라우드**
- **확실한 방법**: AI 에게 `ls functions/.env` 를 시킨다. 있으면 로컬, 없으면 클라우드

데스크탑 화면에 들어갔다고 자동으로 로컬 세션이 되는 것이 아니다.
**「이어서 열면」 클라우드**다. 로컬로 쓰려면 폴더를 지정해 **새로** 시작해야 한다.

### ② 클립보드·파일은 두 컴퓨터 사이를 오가지 않는다

크롬 원격이 보내는 것은 **화면 그림과 마우스·키보드**뿐이다.

- 💻 노트북에서 캡처 → 💻 노트북 창에만 붙는다
- 🖥️ 데스크탑에서 캡처 → 🖥️ 원격 안의 창에만 붙는다

**캡처한 컴퓨터와 대화창이 있는 컴퓨터가 같아야 한다.**

파일을 실제로 옮기려면 구글 드라이브·카톡·이메일 같은 중간 통로가 필요하다.

## 권장 배치 — 탭 두 개

노트북 크롬에 탭을 두 개 두고 쓴다.

| 탭 | 용도 |
|---|---|
| **Remote Access** | 데스크탑에서 실제 작업 |
| **Claude** | 질문·상의 · 노트북 화면 캡처 첨부 |

작업은 원격 탭에서, 캡처가 필요한 대화는 노트북 탭에서.
