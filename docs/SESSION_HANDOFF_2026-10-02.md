## 1. 원격에서 Firestore 에 쓰는 길을 만들었다 (가장 중요)
원격 세션엔 서비스 계정 키가 없어 블로그 글을 쓸 수 없었다. GitHub Secrets 의 `FIREBASE_SERVICE_ACCOUNT_KEY` 를 쓰는 수동 워크플로 둘을 만들었다.

| 워크플로 | 확인 문구 | 하는 일 |
|---|---|---|
| `blog-publish.yml` 「블로그 글 게시 (수동)」 | `게시` | Firestore 전체 백업(아티팩트) → 표지 Storage 업로드 → posts **신규 생성만**. 같은 제목 있으면 건너뜀 |
| `blog-update.yml` 「블로그 본문 수정 (수동)」 | `수정` | 전체 백업 + **기존 본문 파일 백업** → 지금 본문 길이가 `expected_length` 와 다르면 **중단**(사용자가 관리자 화면에서 고친 것) → `content` 만 updateDoc |

- 입력은 **게시 명세 JSON**(`docs/columns/publish/*.json`: title·subtitle·summary·author·category·htmlFile·coverFile·coverDest, 게시 후 postId·lastPublishedLength 기록).
- 길이 대조는 CLAUDE.md 2026-09-24 사건 규칙을 코드로 옮긴 것이다. **수정 성공 뒤 새 길이를 명세의 `lastPublishedLength` 에 갱신**해야 다음 수정이 된다.
- 워크플로 파일은 `main` 에 있어야 실행된다(workflow_dispatch). 실행은 GitHub MCP `actions_run_trigger` 로 했다.
- 개선 여지: 백업 아티팩트가 `backups/` 전체(113MB)를 올린다. 새 백업 파일만 올리도록 좁히면 좋다.
