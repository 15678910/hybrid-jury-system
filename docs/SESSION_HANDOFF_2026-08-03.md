### 1. 파기의 방향 — 파서 완성, 측정은 보류

「파기」가 피고인 상고를 받아들인 것인지 검사 상고를 받아들인 것인지 가리는 파서를
만들었다. **실제 판결문 문언을 먼저 떠서 보고** 규칙을 짰다(`docs/analysis/파기방향_판정설계.md`
에 규칙을 문언 확인 **전에** 못 박아 두었다 — 결과에 맞춰 기준을 고르지 않기 위해).

확인한 실제 표현:
- 「검사가 원심판결에 대하여 상고하였으므로, 대법원은 검사의 상고이유를 판단한다」
- 「이 점을 지적하는 상고이유 주장은 이유 있다」
- 「1. **피고인 1의** 상고이유에 관하여」 ← 피고인이 여럿이면 번호가 붙는다

판정 순서: ① 주문의 파기 대상(무죄부분→검사 / 유죄부분→피고인) ② 상고 주체가 한쪽뿐이면
그쪽 ③ 쌍방이면 각 구간의 「이유 있다」 — 셋 다 아니면 **판정 불가**. 억지로 고르지 않는다.

**첫 측정 결과 (2026-08-07, 형사 전합):**
```
파기 7건 → 피고인 상고 인용 3 / 검사 상고 인용 2 / 판정 불가 2 (판정률 71.4%)
```
**판별 불가다.** 5건에서 3대 2는 양쪽이 대등해도 흔하다(양측 이항검정 **p = 1.0**).
「기운다」의 근거로 쓸 수 없다.

#### 수집기에서 겪은 함정 세 가지 (다시 만나면 여기를 보라)

1. **law.go.kr 은 느리기도 하고, 몰아 쓰면 일시 차단되기도 한다.**
   두 가지가 겹쳐 있어 진단이 어려웠다. 실제 겪은 순서는 이렇다.

   | 실행 | 결과 |
   |---|---|
   | run 2 (13:19) | ✅ 69건 수집 — 다만 연결에만 **10.7초** |
   | run 3~5 (13:25~13:46) | ❌ 연결 타임아웃 → ETIMEDOUT (SYN 무응답) |
   | run 6 (**22:36**, 9시간 뒤) | ✅ 274건 수집, 7분 36초 |

   - **느림**: 첫 연결에 10초 안팎. Node 내장 `fetch`(undici)의 연결 제한이 10초로
     고정돼 있어 매번 경계선에서 잘렸다. 재시도해도 네 번 모두 같은 자리에서 죽는다.
     제한을 지정할 수 있는 `node:https` 로 바꿔 해결했다(기본 60초, `--timeout`).
   - **일시 차단**: 제한을 60초로 늘린 뒤에도 run 5 는 `ETIMEDOUT` 으로 죽었다.
     서버가 거절(RST)한 게 아니라 **아무 응답도 하지 않았다** — 방화벽이 패킷을
     버릴 때의 모습이다. 그런데 9시간 뒤 run 6 은 멀쩡히 성공했다.
     **즉 영구 차단이 아니라 요청량에 따른 일시 차단이다.**

   **교훈 — 한 번 실패했다고 「막혔다」고 단정하지 말고, 몇 시간 뒤 다시 볼 것.**
   그리고 짧은 간격으로 연속 실행하지 말 것. 그것이 차단을 부른다.

2. **`| tee` 가 종료 코드를 삼킨다.**
   수집기가 `exit 1` 로 죽어도 파이프라인의 종료 코드는 `tee` 의 것이라 CI 가 성공으로
   처리했다. 실제로 「0건 수집」이 success 로 보고됐다. `set -o pipefail` 로 막았다.

3. **표본이 작으면 0건이 「없음」처럼 보인다.**
   2쪽만 수집했을 때 전합 표본이 5건뿐이라 일부 파기가 0건으로 나왔다. 같은 실행의
   소부 표본에서는 24.6%였다. **0%를 「그런 결론은 안 나온다」로 읽으면 안 된다.**
   표본 크기를 함께 보라.

## Ⅲ. 조항별 문제 분석 (칼럼 반영 대기)

### ① 제245조의13② — 검사 면담: 일곱 갈래 중 **가장 약한 권리**

> ② 고소인등은 검사에게 면담을 신청하여 의견진술을 할 수 있다. 이 경우 검사는 사실관계 확인의 필요성을 검토하여 **해당 신청의 수리 여부를 결정할 수 있다.**

| 통로 | 상대방 의무 | 거부 사유 제한 | 거부 시 이유 통지 | 불복 |
|---|---|---|---|---|
| 이의신청(제245조의7) | 송치 의무 | — | — | 자동 송치 |
| 이의제기(제245조의11) | 14일 내 통지 | — | — | 상급관서 심사 |
| 열람·등사(제245조의12) | 원칙 허가 | 있음 | **있음** | 없음 |
| **면담(제245조의13②)** | **없음** | **없음** | **없음** | **없음** |

1. **권리가 아니라 재량** — 네 칸이 전부 비어 있음
2. **판단 기준이 신청인의 이익이 아님** — 「사실관계 확인의 필요성」 = 검사의 사건 처리에 도움이 되는가. 조문 제목부터 「**검사의** 사실관계 확인 등」
3. **같은 조문 안의 비대칭** — ⑤항은 피의자에게 변호인 조력 보장, ②항 고소인 면담엔 없음
4. **7대 범죄 피해자 보호는 「부대의견」에만** — 법적 구속력 없음. 부대의견 가.: 「7대 범죄 피해자측이 면담을 신청하는 경우 그 의견을 최대한 들어야 한다」(가정폭력·노인학대·아동청소년성범죄·아동학대·장애인학대·성폭력·스토킹)
5. **말해도 증거로 못 씀**(③) — 취지는 정당(수사·기소 분리)하나 결과적으로 절차적 흔적이 남지 않음
6. 신청 기한·횟수·방식 규정 없음 → 시행령·내부지침 위임

### ② 이의신청 3개월 × 열람·등사 무기한 = **상호 잠금**

- 열람·등사 신청권(제245조의12①)은 목적이 「**제245조의7에 따른 이의신청을 위하여**」로 한정
- 그런데 열람·등사 **처리 기한 규정이 없음**
- 이의신청 기한은 **3개월**

→ **기록을 기다리다 3개월이 지나면 이의신청을 못 하고, 이의신청 기간이 지나면 열람·등사 근거도 사라진다.** 변호인이 있으면 이의신청부터 걸고 기록을 청구하지만, 혼자인 사람은 순서대로 하다 문이 닫힘.

| 항 | 문제 |
|---|---|
| ② 단서 | 제59조의2 사유 + 「**수사의 상황을 고려하여 상당한 이유**」 — 완전히 열린 개념이 원칙 허가를 되돌림 |

### ④ 제245조의11 — 이의제기의 세 겹 약화

1. **3개월 vs 6개월 모순** — 제238조(신설)는 사경이 고소·고발 수리일부터 **3개월 내** 송치 여부 결정하도록 함. 그런데 지연을 다투려면 제245조의11①1호에 따라 **6개월 이상** 실질적 수사 미진행이어야 함. 법이 3개월 안에 끝내라 해놓고 다투는 문은 6개월 뒤에 열림
2. **② 는 조치 의무가 아니라 통지 의무** — 「수사공무원 교체 … 등을 **알려주어야 한다**」
3. **④ 「민원 처리에 관한 법률」 준용** — 준사법적 구제를 행정 민원으로 취급, 반복 이의제기 종결처리 가능

### ⑤ 제245조의7② — 고발인 이의신청 조건부 부활
- 「**대통령령으로 정하는 범죄**」 한정 → 국회가 범위를 정하지 않고 정부에 위임
- 요건이 「직접적인 이해관계가 존재하여 범죄 피해자에 준하는 경우」 — **고발의 본질(이해관계 없는 제3자의 공익 신고)과 어긋남** → 공익신고·내부고발 위축 우려

### ⑥ 제260조 — 재정신청
- 대상 확대 6개 유형 한정 + 「**해당 법률에서 신고할 의무가 있는 자**」로 제한 → **일반 시민 고발인은 여전히 제외**
- 관할 변경(고등법원 6곳 → 지방법원 본원 18곳)은 **접근성 실질 개선 — 긍정 평가할 부분**
- 기각 시 비용부담(제262조의3)은 손대지 않음

### ⑦ 제197조의3⑨ — 안내 의무의 예외
시정조치 신청 절차 안내 의무 신설은 진전이나 「**대통령령으로 정하는 사유**가 있는 때에는 그러하지 아니하다」 단서 있음

# Ⅶ. 신규 검토 — 전원합의체 예측 + 쟁점 분석 기능

> 발단: 유튜브 채널이 「전원합의체 수학적 예측」이라며 한덕수·이상민 사건 결론을
> **75.32% / 10.28% / 9.72% / 4.68%** 로 제시. 우리도 만들 수 있는가?
> **결론: 만들 수 있고, 저 방식을 따라 하지 않으면 이길 수 있다.**

## Ⅶ-0. 사용자가 제공한 핵심 입력 (⚠️ 미검증 — 착수 전 확인 필수)

| # | 입력 | 왜 중요한가 | 검증 방법 |
|---|------|-------------|-----------|
| 1 | **이진관 판사 건만 전원합의체로 회부됐다** | 저 영상은 두 사건이 모두 전합에 있는 것처럼 표를 만들었다. 사실이라면 **저 표의 전제 자체가 틀렸다.** 그리고 선별 회부는 그 자체로 강력한 예측 변수 | 대법원 사건검색, 대법원 공보, 언론 보도 2건 이상 |
| 2 | **한덕수·이상민 변호인단에 양승태 대법원장 시기 인적 네트워크가 걸쳐 있다** | 대리인 구성은 실증 연구에서 실제로 쓰이는 변수 | 변호인 선임계상 이름 → 공개 경력(법원행정처·재판연구관 근무 이력) 대조 |

> ⚠️ **2번은 「측근」이라는 평가어로 사이트에 싣지 말 것.** 명예훼손 위험이 크고 반박당하기도 쉽다.
> 반드시 **검증 가능한 경력 사실**로 분해해 표기한다 (Ⅶ-3 C변수 참조).

## Ⅶ-1. 절대 하지 말 것 (저 영상의 실패)

| 금지 | 이유 |
|------|------|
| **소수점 둘째 자리 확률** (75.32%) | 보정할 데이터가 없다. 전합 회부 사건은 연간 소수이고, 이 사건과 조건이 같은 선례는 사실상 0건. **n≈0에서 소수점 둘째 자리는 나올 수 없다** |
| **AI에게 "확률을 계산해줘"** | LLM은 반드시 그럴듯한 숫자를 만들어낸다. CLAUDE.md 2026-03-18 사건(추론으로 정보 생성)과 같은 패턴 |
| **합계를 100.00에 맞추기** | 75.32+10.28+9.72+4.68 = 100.00 — 숫자를 만든 뒤 정리했다는 신호 |
| **대법관 개인별 확률** | 「A 대법관 유죄 성향 70%」류는 명예훼손 + 재판 독립 침해 비판을 동시에 부른다 |

> 우리 사이트의 자산은 **신뢰성**이다. 근거 없는 확률을 얹으면 우리가 비판해 온 것을 우리가 하게 된다.

## Ⅶ-2. 시스템 구조 — 두 엔진

```
┌─────────────────────────────────────────────────┐
│  A. 쟁점 분석 엔진 (Issue Engine)                │
│     쟁점을 쪼개고, 각 쟁점의 근거·반대근거를 축적  │
│     → 사람이 읽는 결과물. AI 없이도 동작          │
└──────────────────┬──────────────────────────────┘
                   │ 쟁점별 판단이 입력으로
                   ▼
┌─────────────────────────────────────────────────┐
│  B. 예측 엔진 (Prediction Engine)                │
│     기저율 × 변수 보정 → 시나리오별 구간          │
│     → 숫자 결과물. 예측 시점에 박제됨             │
└──────────────────┬──────────────────────────────┘
                   │ 선고 후
                   ▼
┌─────────────────────────────────────────────────┐
│  C. 사후 검증 (Scorecard) ★ 결정적 차별점         │
│     예측 vs 실제 대조, 적중률 영구 공개           │
└─────────────────────────────────────────────────┘
```

**C가 승부처다.** 적중률을 공개하는 예측만이 예측이다. 저 채널은 이걸 하지 않는다(하면 곤란해지니까). 우리가 하면 반년 뒤엔 우리만 남는다. **틀려도 「우리는 틀린 것도 공개한다」가 자산이 된다.**

## Ⅶ-3. 예측 엔진 설계

### 산출 방식 — 기저율에서 출발해 변수로 보정

```
사전확률(기저율)  ──▶  변수별 보정  ──▶  시나리오별 구간
   사법연감              A~D 변수           "55~75%" 형태
```

**절대 규칙**: 최종 출력은 **구간**이고, **정수 단위**이며, **모든 보정에 근거 링크가 붙는다.**
보정 근거를 댈 수 없는 변수는 모델에 넣지 않는다.

### 변수 목록

#### A. 절차 변수 (가장 강력 — 사용자 입력 1번이 여기)

| 변수 | 값 | 방향 | 근거 |
|------|-----|------|------|
| **전합 회부 여부** | 회부 / 소부 유지 | 회부 = 파기·판례변경 가능성 **상향** | 전합 회부 사유 자체가 「판례 변경 필요」 또는 「중대한 법령해석」 |
| **선별 회부** | 두 건 중 한 건만 회부 | **매우 강한 신호** | 같은 사태의 두 사건을 다르게 취급했다는 것은, 회부된 쪽에 소부가 판단할 수 없는 쟁점이 있다는 뜻 |
| 상고 주체 | 검사만 / 피고인만 / 쌍방 | 불이익변경금지 등 결론 범위 제약 | 형사소송법 |
| 심리불속행 여부 | 해당 없음(중형) | — | |

> **선별 회부 변수가 이 사건 분석의 핵심이다.** 저 영상의 표는 두 사건을 하나의 확률 공간에 넣었는데,
> 애초에 **절차적 지위가 다르다면 그 표는 성립하지 않는다.** 이 지점을 짚는 것만으로 우리 콘텐츠가 이긴다.

#### B. 재판부 변수 — **개인별 금지, 구성 단위로만**

| 허용 | 금지 |

## Ⅶ-4. 쟁점 분석 엔진 설계

예측보다 **이쪽이 본체다.** AI 없이도 완전히 동작하고, 법적 리스크가 낮으며, 재사용된다.

### 쟁점 카드 구조

각 쟁점 하나가 카드 하나. 예시 (⚠️ 실제 쟁점은 판결문·보도로 확정할 것):

```
쟁점 #1  내란죄의 「국헌문란 목적」 인정 범위
├─ 원심 판단     : (2심이 어떻게 봤는지 + 판결문 인용)
├─ 상고 이유     : (상고인이 무엇을 다투는지)
├─ 관련 선례     : (대법원 판례 번호 + 링크)
├─ 파기 쪽 근거  : ● ● ●        (각각 출처 링크)
├─ 확정 쪽 근거  : ● ●
└─ 판단          : 확정 우세 / 다툼 팽팽 / 파기 우세  ← 확률 아님
```

### 왜 이게 확률보다 나은가

1. **틀려도 무너지지 않는다.** 근거를 제시했고 독자가 판단했다
2. **재사용된다.** 다른 사건에도 같은 틀을 쓴다 → 사이트의 영구 자산
3. **AI가 필요 없다.** 비용 0
4. **검증당해도 이긴다.** 각 근거에 출처가 붙어 있다

## Ⅶ-5. Firestore 스키마 (초안)

```
predictions/{caseId}
  ├─ caseTitle, courtLevel, caseNumber
  ├─ isEnBanc: bool              // 전합 회부 여부
  ├─ enBancSelective: bool       // 선별 회부 (사용자 입력 1)
  ├─ baseRate: { value, source, year }
  ├─ variables: [ { code, label, direction, weight, sourceUrl } ]
  ├─ scenarios: [ { label, rangeLow, rangeHigh, rationale } ]
  ├─ predictedAt: timestamp      // ★ 박제 시점
  ├─ lockedAt: timestamp         // 선고 임박 시 갱신 중단 시점
  └─ locked: bool

issues/{caseId}/items/{issueId}
  ├─ title, order
  ├─ lowerCourtHolding, appealGround, precedents[]
  ├─ argsForReversal: [ { text, sourceUrl } ]
  ├─ argsForAffirm:   [ { text, sourceUrl } ]
  └─ verdict: 'affirm-lean' | 'contested' | 'reverse-lean'

outcomes/{caseId}                // 선고 후 기록
  ├─ actualResult, decidedAt, judgmentUrl
  └─ hit: bool, note
```

**규칙: `predictedAt` 이후 `scenarios`는 수정 금지.** 수정하면 예측이 아니다.
정정이 필요하면 새 문서를 만들고 이전 예측도 함께 보존한다.

## Ⅶ-7. 리스크 통제 (필수)

| 리스크 | 통제 |
|--------|------|
| 재판 영향·여론재판 비판 | 페이지 제목을 「예측」이 아니라 **「쟁점 분석」**으로. 예측은 하위 요소 |
| 선고 임박 시점 논란 | **선고 예정일 7일 전부터 갱신 중단**(`locked: true`), 배너 고지 |
| 대법관 명예훼손 | 개인별 예측 금지. 재판부 구성 단위로만 |
| 변호인 명예훼손 | 평가어 금지, 공개 경력 사실만 + 「편향을 의미하지 않는다」 고지 병기 |
| AI 환각 | 확률 생성에 LLM을 쓰지 않는다. AI는 **서술 요약**에만 |
| 오보 확산 | 모든 수치에 출처 링크 필수. 출처 없으면 게시 금지 |
